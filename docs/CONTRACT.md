# T04-Scnr CPU — implementation contract
Project is a prototype security analysis console, NOT universal malware/backdoor detector.
Runtime CPU only. Default static scanning NEVER instantiates model, calls torch.load/pickle.load, imports uploaded code, or runs inference. Learned RF weight-forensics uses F32 safetensors only; F16/BF16 have separate descriptive mantissa statistics. ModelAudit isolated optional subprocess, with fixed command, no shell, timeout, unsafe loaders OFF. No network during a scan. Network retrieval is confined to explicit preparation commands, plus the separate consent-gated Groq Evidence Assistant request. Scanning, offline interpretation and PDF export never call Groq. No other hosted LLM provider is supported.
Separate findings: static file indicators; statistical weight anomalies; learned controlled-manipulation score; reference changes; known-trigger behavioral verification. Not analyzed != no finding. No combined probability of malware or TRUSTED verdict.
Artifact/report UUIDs generated by app. Uploads staged with random names; sanitized original name as display only. All state under explicitly configured STEGOGATE_DATA_DIR. Report path selection by validated IDs, not arbitrary user paths. Bind localhost only initially. No secret values in repo.
## Paths and ownership
- Orchestrator owns stegogate/{__init__,schemas,pipeline,cli,storage}.py, pyproject.toml, requirements*, README, scripts/setup*, integration tests.
- Core agent owns stegogate/{intake,features,reference,static_scan}.py and tests/test_core*.py.
- ML agent owns stegogate/ml.py, scripts/train_detector.py, tests/test_ml*.py, docs/ML.md.
- Demo agent owns stegogate/demo.py, scripts/prepare_demos.py, tests/test_demo*.py, docs/DEMOS.md and demo manifest under docs/demo_sources.json. Shared downloaded data under data/demo/. It may own scripts/validate_demos.py. DO NOT install authentrics or use APIs. No automatic conversion of arbitrary .pt.
- UI agent owns app.py, stegogate/ui_helpers.py, tests/test_ui*.py, docs/DASHBOARD.md. May own assets/. No changes to pipeline/schema.
No agent commits shared git or edits another agent's files. Files shared locally; orchestrator deploys/tests on VM. No external code copied without compatible license+attribution. Prefer dependency adapters/own original code.
## Interfaces (Python, plain JSON-safe dicts)
intake.inspect_artifact(path: str|Path, config: dict|None=None)->dict:
 {format: 'safetensors'|'pytorch_zip'|'pickle'|'unknown', size_bytes:int, sha256:str, tensors:list[dict], metadata:dict, errors:list[str], warnings:list[str]}
Tensor dict: {name,dtype,shape:list[int],data_offsets:[int,int],numel,nbytes}. Offsets relative to safetensors data start. Extra internal header_bytes allowed; raw data excluded from report. Structural invalidity must be explicit. Reject duplicate JSON keys, overlap/gaps/invalid dtype/size/shape, bound header/names/numel/file size. Default max_artifact_bytes=256MiB, max_header_bytes=8MiB.
features.analyze_weights(path, inventory:dict, config:dict|None=None)->dict:
 {status:'completed'|'partial'|'unsupported'|'failed', feature_names:list[str], windows:list[dict], tensor_summaries:list[dict], coverage:dict, warnings:list[str]}
Window {tensor:str, window_index:int, element_start:int, element_count:int, features:dict[str,float], anomaly_score:float, evidence:list[str]}. Use deterministic evenly spaced sampling bounded total (max_windows=128 default, window_elements=4096); F32 only; finite values; skip with reasons. Raw bit planes low 0..7 meaningful for F32. Natural LSB near randomness, theoretical heuristics not proof. Features numeric and finite, names stable. No absolute sample-index/name/model-ID features for ML. Score heuristic explicit uncalibrated unless data supports calibration.
reference.compare_reference(path,reference_path,config=None)->dict {status,summary:dict,tensors:list[dict],warnings:list[str]}; validate both; only compatible names/shapes/dtypes; hashes. Never changes imply malicious.
static_scan.run_modelaudit(path,config=None)->dict {status:'completed'|'unavailable'|'failed'|'timed_out'|'partial',findings:list[dict],engine_version:str|None,warnings:list[str],duration_seconds:float}; bounded subprocess output. No claim 'passed' from exit code alone.
ml.train_detector(rows:list[dict],output_dir:str|Path,config=None)->dict. Each row {features:dict,label:int,lineage:str,variant:str(optional)}. Whole-lineage train/val/test partition, pre-split preprocessing, test only once. Save detector.json + detector_manifest.json, NO untrusted pickle loading. Can JSON serialize RF tree arrays and custom infer to avoid joblib. Artifact clearly states training data scope. Missing adequate lineages fails or marks exploratory. No manufactured performance. Returned training result JSON safe with metrics+scope.
ml.score_windows(windows:list[dict],detector_path:str|Path|None=None)->dict {status:'completed'|'not_available'|'failed',scores:list[dict],manifest:dict,warnings:list[str]}; score row identifies tensor+window_index, score float labelled model vote not malware probability. Trusted app-owned detector path only. Missing features fail safely.
demo.get_demo_catalog()->list[dict]; demo.prepare_demo(demo_id:str,root:Path,config=None)->dict; demo.verify_behavior(demo_id:str,root:Path,config=None)->dict. Only hardcoded allowlisted IDs; all explicit opt-in; pinned revisions+hashes manifest. Behavior code uses reviewed local architecture, CPU, no remote custom code, no unsafe torch.load. Restricted weights_only for pinned .pt PREPARATION ONLY isolated process, artifact cap, no allowlist_globals. refuse unknown objects. ## v0.4 interpretation and PDF boundaries
Scan reports remain immutable schema 1.0/1.1. Interpretations are separate report-hash-bound objects. Groq request uses only an explicitly previewed allowlisted numeric/enumerated evidence projection; no raw weights, names, paths, hashes, free-form messages, tools or provider fallback. Strict schema and reference validation do not establish prose truth. Groq text is labelled unverified, rendered as plain text, and cannot alter scanner output. Default offline interpretation and ReportLab PDF export remain local/CPU. PDF appendix is opt-in, hash-matched and visibly separate. Keys are server-side environment only within API adapter, optional launcher-owned mode600 key file, never UI/session/export values.

## v0.5 native host adapters
The report schema remains 1.1. Runtime adds explicit `peak_rss_unit`, `rss_source`, `platform` and host capabilities; legacy `peak_rss_mb` is retained. Windows peak working-set bytes and Linux ru_maxrss KiB are normalized to MiB; unavailable measurements are null. Native Windows provides tensor/reference/RF/report/cloud paths but not the Linux-isolated static scanners or demo workers. Unsupported checks remain unavailable/not-performed and do not become passes. Windows default state is under LOCALAPPDATA. See WINDOWS.md.
